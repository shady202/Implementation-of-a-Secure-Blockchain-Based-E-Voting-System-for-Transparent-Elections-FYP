### 1.1 System Architecture Diagram

> **Status**: ✅ **Complete** - Professional diagram created  
> **Diagram File**: [SYSTEM_ARCHITECTURE_DIAGRAM.md](./SYSTEM_ARCHITECTURE_DIAGRAM.md) - Comprehensive Mermaid diagram with detailed explanations  
> **Alternative Format**: [system-architecture.drawio](./system-architecture.drawio) - Draw.io format  
> **Detailed Explanation**: [system-architecture-explanation.md](./system-architecture-explanation.md)

**Description**:
The System Architecture Diagram illustrates the comprehensive, multi-layered structure of the blockchain-based e-voting system. It demonstrates the interaction between the frontend (React/Vite), backend (Node.js/Express), blockchain layer (Ethereum/Hoodi Network), database (PostgreSQL), and external services, ensuring secure, transparent, and tamper-proof voting.

**Key Features**:

- **8 Distinct Layers**: Client, Presentation, Blockchain Integration, Application, Blockchain, Data, External Services, Security & Monitoring
- **Professional Styling**: Color-coded layers with clear visual hierarchy
- **Comprehensive Components**: All major system components with technical details and versions
- **Clear Data Flows**: Labeled connections showing communication protocols and data flow patterns
- **Security Indicators**: Visual markers for security and immutability features
- **Complete Documentation**: Detailed explanations of each layer, technology stack, and data flows

**Architectural Layers**:

1. **CLIENT LAYER**: Web browsers, MetaMask wallet, mobile devices, user types
2. **PRESENTATION LAYER**: React 19.1.0 + Vite 6.3.5, React components, UI framework, state management
3. **BLOCKCHAIN INTEGRATION LAYER**: ethers.js, contract interface, network configuration, MetaMask provider
4. **APPLICATION LAYER**: Express server, API endpoints, authentication, OTP service, email service, session management
5. **BLOCKCHAIN LAYER**: Hoodi Network, voting smart contract, candidate management, vote recording functions
6. **DATA LAYER**: PostgreSQL database with voter records, election metadata, vote history, system settings
7. **EXTERNAL SERVICES**: SMTP email server, RPC provider for blockchain access, MetaMask extension
8. **SECURITY & MONITORING**: JWT auth, OTP verification, rate limiting, audit logging, HTTPS/TLS

**Communication Protocols**:

- **HTTPS/TLS**: Secure client-server communication
- **REST API (JSON)**: Frontend-backend data exchange
- **Web3 Provider**: Blockchain interaction via MetaMask
- **SQL**: Database CRUD operations
- **SMTP**: Email delivery for OTP
- **JSON-RPC**: Blockchain network access

**Security Architecture**:

- Multi-layer security approach from client to database
- JWT authentication and authorization
- Blockchain immutability and transparency
- Input validation and sanitization
- Encrypted connections (HTTPS, TLS)

## 3. RAD Methodology Design Emphasis

### 3.1 Rapid Prototyping Approach

The design phase utilized rapid prototyping to quickly build functional prototypes of key features:

- **Initial Prototype**: Basic voting interface with MetaMask integration
- **Iterative Enhancements**: Added OTP verification, admin dashboard, capacity management
- **User Testing**: Continuous testing with stakeholders to refine features

### 3.2 Iterative Design Cycles

The system was developed through multiple short iterations:

1. **Iteration 1**: Core voting functionality
2. **Iteration 2**: User authentication and security
3. **Iteration 3**: Admin controls and monitoring
4. **Iteration 4**: Performance optimization and capacity management

### 3.3 User Feedback Integration

Design decisions were driven by user feedback:

- **Voter Experience**: Simplified registration process based on user testing
- **Admin Dashboard**: Enhanced monitoring capabilities per administrator requests
- **Mobile Responsiveness**: Improved mobile UI after mobile device testing

### 3.4 Quick Turnaround Strategy

RAD enabled rapid response to requirements:

- **Agile Sprints**: 1-2 week development cycles
- **Continuous Deployment**: Immediate testing of new features
- **Flexible Architecture**: Modular design allowing quick modifications
