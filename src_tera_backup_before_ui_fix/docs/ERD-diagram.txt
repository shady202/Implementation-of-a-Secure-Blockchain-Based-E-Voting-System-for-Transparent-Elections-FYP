═══════════════════════════════════════════════════════════════════════════════
  KEY CONSTRAINTS AND RULES
═══════════════════════════════════════════════════════════════════════════════

1. UNIQUE CONSTRAINTS:
   ├─ users.email             → Each email can only be used once
   ├─ users.tp_number         → Each student ID is unique
   ├─ users.wallet_address    → Each wallet can only link to one user
   ├─ candidates (user_id, category_id, election_id) → One candidacy per position
   └─ votes (user_id, category_id, election_id) → ONE VOTE per user per category

2. CHECK CONSTRAINTS:
   ├─ users.tp_number         → Must match pattern: TP[0-9]{6}
   ├─ users.wallet_address    → Must match pattern: 0x[a-fA-F0-9]{40}
   ├─ users.year_of_study     → Must be between 1 and 4
   ├─ elections.end_time      → Must be greater than start_time
   ├─ categories              → Maximum 3 categories per election
   ├─ candidates.vote_count   → Must be >= 0
   └─ votes.blockchain_tx_hash → Must match pattern: 0x[a-fA-F0-9]{64}

3. CASCADING RULES:
   ├─ users.id → auth.users.id          ON DELETE CASCADE
   ├─ categories.election_id → elections ON DELETE CASCADE
   ├─ candidates.category_id → categories ON DELETE CASCADE
   ├─ candidates.election_id → elections ON DELETE CASCADE
   ├─ votes.candidate_id → candidates    ON DELETE CASCADE
   ├─ votes.category_id → categories     ON DELETE CASCADE
   └─ votes.election_id → elections      ON DELETE CASCADE

4. IMMUTABLE TABLES (No UPDATE or DELETE):
   └─ votes (except super_admin DELETE only)
   └─ audit_logs (completely immutable)

5. AUTO-INCREMENT TRIGGERS:
   ├─ candidates.vote_count   → Incremented on vote INSERT
   ├─ elections.current_voters → Incremented on vote INSERT
   ├─ users.is_verified       → Synced from auth.users.email_confirmed_at
   └─ *.updated_at            → Auto-updated on row UPDATE
